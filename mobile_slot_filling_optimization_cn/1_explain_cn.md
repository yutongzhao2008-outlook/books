# 如何在手机上优化端侧槽位填充

主题：优化手机上的 `slot_filling_ondevice.html`。
规则：句子要短。一句只讲一个意思。用简单的词。

## 为什么慢

1. 模型运行在手机上。
2. 手机的内存比服务器少。
3. 手机的算力比服务器弱。
4. 速度取决于三类成本。
5. 第一类成本是读取 Token。每一轮都要读 Prompt。
6. 第二类成本是写出 Token。模型一次只写一个 Token。
7. 第三类成本是加载模型。加载需要几秒钟。

## 怎么做

### 1. 把模型变小

8. 使用 5 亿或 15 亿参数的模型。
9. 使用 Q4_K_M 量化。
10. 小模型占用的内存更少。
11. 小模型运行得更快。
12. 准确率可能下降。要测试。

### 2. 让 Prompt 变短

13. 把固定文字放在最前面。
14. 每一轮固定文字都保持不变。
15. 开启 `cache_prompt`。
16. 被缓存的部分不会重新计算。
17. 固定部分之后，只发送用户的新话。

### 3. 限制输出

18. 把 `n_predict` 设为 64。
19. 输出是一个小的 JSON 对象。
20. JSON 闭合时停止。
21. 把 `temperature` 设为 0。

### 4. 让上下文变小

22. 使用 `-c 512` 到 `-c 1024`。
23. 长上下文占用更多内存。
24. 长上下文还会让每一步变慢。

### 5. 只启动一次服务

25. 应用启动时，启动一次 `llama-server`。
26. 保持它常驻运行。
27. 不要在每次请求时重新加载模型。

### 6. 用好手机的硬件

28. 线程数设为快速 CPU 核心的数量。
29. 分别测试 2、4、6 个线程。
30. 只有在编译版本支持时，才使用 GPU 或 NPU 层。
31. 每一项改动都要在真机上测试。

### 7. 先用规则，再用模型

32. 日期在代码中转换。例如“明天”变成 `2026-10-20`。
33. 数字在代码中转换。
34. 不要让模型做日期计算。
35. 模型只负责抽取。由代码做决定。

### 8. 每次改动前后都要测量

36. 测量首 Token 延迟。
37. 测量总延迟。
38. 测量峰值内存。
39. 连续使用 5 分钟后再测一次。手机发热后会变慢。
40. 每次只改一项。

### 9. 每次改动后检查准确率

41. 每次改动后，用同一测试集测试。
42. 速度再快，槽位错了也没有用。
43. 如果准确率下降，撤销最后一项改动。

## 总结

44. 把模型变小。
45. 让 Prompt 变短，并使用缓存。
46. 限制输出长度。
47. 让服务保持运行。
48. 日期和数字交给代码处理。
49. 测量，然后只改一项。
