# 图示：如何在手机上优化端侧槽位填充

## 1. 请求流程（每一轮都会执行）

```mermaid
flowchart LR
  A[用户语音或文字] --> B[规则归一化<br/>日期、数字]
  B --> C[短 Prompt<br/>固定前缀放最前]
  C --> D{前缀在 KV 缓存中？}
  D -- 是 --> E[只处理新 Token]
  D -- 否 --> F[处理完整 Prompt]
  E --> G[llama-server<br/>Q4 模型、json_schema、<br/>n_predict = 64]
  F --> G
  G --> H[解析与校验]
  H --> I[合并状态]
```

## 2. 时间花在哪里

```
总延迟
├── 加载模型        （避免：只启动一次服务）
├── 读取 Prompt     （减少：Prompt 变短 + cache_prompt）
│   └── Prefill Token
└── 写出输出        （减少：n_predict = 64，JSON 闭合即停）
    └── Decode Token
```

## 3. 优化杠杆

```mermaid
flowchart TD
  M[目标：快、准确、内存低] --> L1[更小的模型<br/>0.5B-1.5B，Q4_K_M]
  M --> L2[更短的 Prompt<br/>固定前缀 + cache_prompt]
  M --> L3[限制输出<br/>n_predict，temperature 0]
  M --> L4[小上下文<br/>-c 512 到 1024]
  M --> L5[常驻服务<br/>只启动一次，-np 1]
  M --> L6[硬件调优<br/>线程数，GPU/NPU 层]
  M --> L7[规则优先<br/>日期和数字在代码中处理]
  L1 --> V{准确率测试<br/>是否仍然通过？}
  L2 --> V
  L3 --> V
  L4 --> V
  L5 --> V
  L6 --> V
  L7 --> V
  V -- 否 --> U[撤销最后一项改动]
  V -- 是 --> K[保留改动，再次测量]
```

## 4. 杠杆一览表

| 杠杆 | 改动 | 效果 | 风险 |
|---|---|---|---|
| 模型大小 | 1.5B → 0.5B，Q4_K_M | 内存更少，解码更快 | 准确率下降 |
| Prompt 缓存 | `cache_prompt: true`，固定前缀放最前 | 每轮的 prefill 更少 | 前缀不能改变 |
| 输出上限 | `n_predict: 64` | 限制过长输出 | 太小会截断 JSON |
| 上下文 | 用 `-c 1024` 代替 4096 | 每一步内存更少 | 长对话需要裁剪状态 |
| 常驻服务 | 只启动一次 `llama-server` | 去掉加载时间 | 后台占用内存 |
| 线程数 | 与快核数量匹配（测试 2 / 4 / 6） | 推理更快 | 发热和耗电 |
| 规则 | 日期和数字在代码中归一化 | 模型出错更少 | 需要维护更多代码 |

## 5. 测量循环

```
 基线 ──► 只改一项杠杆 ──► 测量延迟与内存
   ▲                              │
   │                              ▼
 撤销 ◄──── 准确率下降？ ◄──── 同一测试集测准确率
                                  │ 没有下降
                                  ▼
                           保留改动，改下一项
```
